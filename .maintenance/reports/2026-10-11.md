## 追加运行（2026-10-11 下午，手动触发；目标：把 superpowers 在 DSH 上需要的东西搭起来）

### 查到的真实缺口

技能正文用 `bash scripts/<name>` 与裸路径 `scripts/task-start PLAN N` 调用 helper。本机 `bash` 在 PATH 里解析到
`C:\Windows\system32\bash.exe`（Microsoft Bash Launcher），它执行的是 **WSL 的默认发行版**；而本机默认发行版是
`docker-desktop`——Docker Desktop 的轻量发行版，**里面只有 `ash` / `sh`，没有 `/bin/bash`**，于是每次调用都是
`execvpe(/bin/bash) failed: No such file or directory`（exit=1）。WSL 本身完全正常：`wsl -e echo OK` → exit=0，
WSL 2.6.3.0 / 内核 6.6.87.2-1，另装有 `Ubuntu` 26.04 LTS（Stopped）。因此技能里所有 bash 调用、以及所有裸路径
调用（Windows 无 shebang）**全部不可用**。而 `sh` 指向 Git Bash（`C:\Program Files\Git\bin\sh.exe`），可用。

> **修正（2026-10-11 晚，作者指出后复核）**：本节初稿写作「WSL 没有安装发行版」，不准确。WSL 已安装且发行版齐备，
> 真正原因是**默认发行版落在 `docker-desktop` 上**（该发行版不含 bash）。已同步修正 `references/dsh-tools.md`
> 的同一处描述，并补上第二种修法 `wsl --set-default Ubuntu`（仅在接受 Linux 路径视图时使用，未擅自改动本机默认发行版）。
